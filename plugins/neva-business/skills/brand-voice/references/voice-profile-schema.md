# Voice Profile Schema

Use this exact structure when building a reusable voice profile:

```text
VOICE PROFILE
=============
Author:
Goal:
Confidence:
Last confirmed:

Source Set
- source 1
- source 2
- source 3

The Test
- one line the author would use to judge a draft (for example: would a normal person say this out loud)

Registers
- surface: register (for example: public posts: sharp, opinionated / client documents: calm, restrained)

Languages
- language: variety and register per platform
- loanwords: terms written as practitioners say them, never translated

Rhythm
- sentence length, pacing, fragmentation

Compression
- how dense or explanatory the writing is

Capitalization
- conventional, mixed, or situational

Parentheticals
- how they are used and how they are not

Question Use
- rare, frequent, rhetorical, direct, or mostly absent

Claim Style
- how claims are framed, supported, and sharpened

Proven Structures
- sentence shapes the author reuses, with one real example each

Lexicon
- required words and phrases
- forbidden words and phrases

Preferred Moves
- concrete moves the author does use

Banned Moves
- specific patterns the author does not use

Format Rules
- thing: rule (for example: blog titles: single phrase, no colon split)

CTA Rules
- how, when, or whether to close with asks

Channel Notes
- X:
- LinkedIn:
- Instagram:
- Email:

Accepted and Rejected Log
| date | line | verdict | reason |
```

Guidelines:

- Keep the profile concrete and source-backed.
- Use short bullets, not essay paragraphs.
- Every banned move is observable in the source set or explicitly requested by the user.
- If sources conflict, call out the split instead of averaging it into mush.
- The log only grows. Never delete a rejected line; it is the cheapest regression test the voice has.
